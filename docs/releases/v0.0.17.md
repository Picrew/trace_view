# Trace Review v0.0.17

## Turn 参数可见 + Session 级信息

Review 一个 trace 时最常问的问题之一是"这个 turn 是用什么配置跑的"——模型、effort、权限、沙箱。之前 boundary 行只有 `Request N · model · 时长`，这一版把 turn 级参数和 token 用量画上去，session 级的花费 / 行数 / PR 也进 header。

### Boundary 行（每个 Request）

| 来源 | 字段 | 示例 |
|------|------|------|
| Codex `turn_context` | `effort` / `approval_policy` / `sandbox_policy` | `Request 2 · gpt-6-astra · xhigh · never · danger-full-access` |
| Codex `token_count` | 每 turn token 用量 | `… · ↑335k ↓17k` |
| Claude Code `api-request` | `effort` / `thinking` / `max_tokens` | `Request 1 · claude-opus-5-5 · xhigh · bypassPermissions · thinking:adaptive` |
| Claude Code `permission-mode` | 权限模式 | （同上，`bypassPermissions`） |

实现要点：CC 的参数行在 assistant 行**之前**出现且无 timestamp——adapter 用 pending 槽位收集，下一条 derived boundary 消费后清空；Codex 的 `token_count` 晚于 boundary 到达——boundary 事件对象原地补丁（`last_token_usage` 是该 turn 的增量，取 max 防重复）。

### Run Header

- **`$` 总花费** + **`+/−` 行数**（`cost-state`，随 session 刷新取最新）
- **PR 链接**（`pr-link`）——可点击直达
- **subagent 名**（`agent-name`）进 notes

### 噪音清理

`api-request` / `api-request-blob` / `api-request-shape` / `tools-used` / `file-history-*` / `permission-mode` 这些每请求重复出现的簿记行，之前全部落进 unknown 事件（实测一个 102-request 的 CC session 有 **220 条** unknown 噪音行）。现在归入 `skippedTypes` 静默统计，权限模式转由 boundary 行承载——unknown 只留给真正未识别的行。

**验证**：69/69 测试（新增 9 个：codex turn_context 参数与 none 值、token_count 折进 boundary、CC api-request/permission-mode 上 boundary、cost-state/pr-link/agent-name、噪音行归零）。真实数据：CC session boundary 带 `xhigh · adaptive · 128000`、`$10.94 · +349/−52`、PR #1、unknown 220 → **0**；Codex session boundary 带 `gpt-6-astra · xhigh · never · danger-full-access · ↑335k ↓17k`。
