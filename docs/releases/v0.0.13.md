# Trace Review v0.0.13

## 修复：大部分历史 Codex 会话从库里消失

Codex 会把已结束的 rollout 原地压缩：`rollout-*.jsonl` → `rollout-*.jsonl.zst`，`~/.codex/sessions/YYYY/MM/DD/` 和 `~/.codex/archived_sessions/` 下都有。扫描器只认 `.jsonl` / `.ndjson` 后缀，压缩过的会话全部不可见——数据还在磁盘上，只是库里看不到。表现是会话总数突然大幅下降，看起来像历史被删了。

本机实测：Codex 在 2026-10-22 一次压缩了 745 个 rollout，库里的会话从约 1060 掉到 288。这一版之后回到 **1044**（codex 26 → 780，2025-09 至 2026-11 每个月都在）。

- `.jsonl.zst` / `.ndjson.zst` 透明解压，用 Node 内置 zstd（`zlib.createZstdDecompress`），不新增依赖。库扫描、完整解析、raw JSON、搜索都支持
- 所有 offset 按解压后字节计；zstd 不能随机访问，raw 切片从头流式解压，读够即停
- run id 忽略 `.zst` 后缀：会话被 Codex 压缩后 id 不变，`#run=` 链接继续有效；已打开的会话会自动切到新文件重新解析
- 压缩进行中 `x.jsonl` 和 `x.jsonl.zst` 同时存在时只保留明文版本，不会重复
- 解析预算按 zstd 帧头记录的解压后大小计算（磁盘上约为实际内容的 1/3）
- 手动导入也接受 `.jsonl.zst`
- 运行时 Node 低于 22.15 时自动跳过 `.zst`，不报错（打包版内置 Node 23.10）

**验证**：47/47 测试（新增 `tests/zst.test.ts`：3 MB 含中文文件压缩前后逐行、跨块切片、头尾读取一致；codex fixture 压缩前后事件、统计、id 完全一致；扫描收集 zst 且明文优先）。真实数据冷扫描 5.2 s、缓存命中 24 ms；最大会话 251 MB（解压后 437 MB）完整解析 1.6 s，最后一个事件的 raw JSON 0.4 s。

> 注：升级后第一次打开会全量扫描新增的压缩会话，库列表需要几秒才出来，之后走缓存。
