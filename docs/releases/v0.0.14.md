# Trace Review v0.0.14

## 优化：搜索命中直接可见

之前搜索只把匹配列表列在下拉里——事件流里命中的行没有任何标注，命中的文字没有高亮，"匹配在哪"只能靠点一条看一条。这一版把命中位置直接画在界面的每一层：

- **事件流文字高亮**：命中的文字在消息正文（markdown）、reasoning、tool 输出（stdout/stderr）、diff、file 路径里全部下划线高亮（琥珀色，全小写不敏感，标出每一处出现）
- **行级标注**：命中的行在时间列加琥珀标记点；聚合行显示 `N` 个命中的角标
- **Timeline 标注**：命中的 span 在时间轴上加琥珀描边，当前匹配实心填充——顺着时间轴一眼看到命中分布
- **自动跳转**：搜索结果回来时直接跳到第一个命中并滚动到屏幕中央（之前匹配行在虚拟视口外时什么都看不到，这是这次最实质的修复）
- **键盘导航**：`⌘F` 聚焦搜索框；`Enter` / `Shift+Enter` 下一个 / 上一个；`↑` 下一个；`Esc` 清空。输入框旁新增 `n/N` 计数器和 ‹ › 步进按钮
- **reasoning 自动展开**：命中在折叠的 reasoning 里时自动展开，保证高亮可见
- **结果弹层不再常驻**：聚焦搜索框时展开，失焦自动收起；结果超过 50 条时标明只显示前 50

搜索仍走服务端全文匹配（大小写不敏感），高亮与匹配语义一致（同一查询、同一处命中）。

**验证**：49/49 测试（新增搜索流 UI 测试：popover 高亮、计数、Enter 步进、Esc 清空；highlight 工具单测）。真实浏览器实测：事件流高亮、timeline 描边、n/N 计数、Enter 步进（1/7 → 3/7）、blur 收起弹层、无匹配与 Esc 状态。

> 注：jsdom 测试环境无法测量虚拟化视口，行级标注的视觉验证走真实浏览器截图（`scripts/visual-snapshot.ts` 的 06-search 状态）。
