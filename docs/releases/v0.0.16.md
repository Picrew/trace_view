# Trace Review v0.0.16

## 修复：Session 标题与官方 UI 对齐

同一个会话，在 Claude Code / Codex 里是一个标题，在 Trace Review 里却是"第一条用户消息"截断——标题来源没对上官方。这一版把两侧的权威标题来源都接进来：

### Claude Code：`ai-title` 行

- 新版 CLI（v2.1.270+）把 resume 列表里显示的标题写进 **`ai-title`** 行（`aiTitle` 字段），随对话演进反复刷新——Trace Review 之前不认识这个行类型（落到 unknown），标题只能回退到第一条用户消息
- 现在**取最后一次出现的值**（与 CLI 行为一致）；旧版的 `custom-title`（用户手动改名）依然永远优先
- 大会话（>512KB）的标题行可能落在 head 预算之外——tail 再扫一遍兜底，标题行 CLI 会持续写在文件尾部附近

### Codex：`session_index.jsonl`

- rollout 文件里**根本没有标题**——Codex UI 的标题存在 `~/.codex/session_index.jsonl`（`{id, thread_name, updated_at}` 追加式，后行覆盖前行）
- 新增 `CodexTitleIndex`：按 sessionId → 最新 `thread_name`，索引文件 mtime 缓存；索引更新（会话改名）时相关 rollout 的 summary 缓存自动失效重扫
- 归档会话（`archived_sessions/`）不在索引里，回退首条用户消息——与 Codex 自身行为一致
- 详情页标题与列表同源：`loadRun` 把列表侧解析出的官方标题同步给 run

### 优先级（与官方 UI 对齐）

| 来源 | 优先级 |
|------|--------|
| Claude Code `custom-title`（用户手动改名） | 最高 |
| Claude Code `ai-title`（最新值）/ Codex 索引 `thread_name` | 次之 |
| 第一条用户消息 | 兜底 |
| 文件名 | 最后兜底 |

**验证**：60/60 测试（新增 10 个：ai-title 多值取最后、custom-title 优先级、tail 兜底、Codex 索引解析与 resolver 注入、索引缺失回退）。真实数据实测：本机 Claude Code 会话 **8/8** 标题与 `claude --resume` 显示一致（含两个标题行在 850KB/1.3MB 偏移处的大文件）；Codex 11 月会话 **30/30** 与 session_index `thread_name` 一致。
